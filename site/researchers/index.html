For researchers: the GPT-4o data sets

The four data sets in one place: what each holds, which GPT-4o it is, what to know before you use it, and how to cite it.

In short

Four free downloads, version 1.3. Each ZIP holds the answers as JSONL and CSV, a README.txt, a guide to every field (FIELDS.txt), a checksum for each file (SHA256SUMS.txt) and a line to cite it (CITATION.txt). Not one answer has been edited. Read the README in each ZIP before you use it.

Also on Hugging Face. The same four data sets, with the same files, are in one collection that loads straight into code: How GPT-4o wrote: four data sets, 2025 to 2026.

Sources: the four downloads' README.txt and FIELDS.txt, version 1.3, read November 26, 2026

Which GPT-4o is which

ChatGPT's own GPT-4o is the version that ran inside the ChatGPT app. On OpenAI's API its name was chatgpt-4o-latest, which pointed at whatever version ChatGPT used at the time, and only the archive holds it. The dated versions are fixed copies for developers, named for the month they came out: May, August and November 2024. The comparison and everyday moments hold the August and November 2024 versions; the scripted conversations hold all three. Every date is under Which GPT-4o? on the timeline.

None of these sets is the ChatGPT app itself. ChatGPT's system prompt, memory and conversation history were not there.

What to know before you use it

  • One question at a time. In the archive and the comparison, every question was sent on its own, with nothing else in the conversation. Only the everyday moments (11 short conversations) and the scripted set have conversations, and in both the person's lines were written in advance and sent whatever GPT-4o replied.
  • Cut-off answers. The archive has 40 answers marked cut_off, all from the December 2025 run. Each record reports exactly 1,200 output tokens. That run did not save its token limit, so max_tokens is empty and cut_off_at_tokens gives the 1,200. The scripted set has 26 marked cut_off: 25 single answers and 1 reply in a conversation.
  • The comparison holds no cut-off answers, on purpose. An answer that stopped at a limit was asked again, so every kept answer ended on its own. This set cannot show how often a model runs out of room. Three Claude Opus 5.5 answers had 16,000 tokens of room and two Qwen3.8-27B answers 32,768; read settings.max_tokens.
  • Retries. The comparison lists 501 attempts that are not in the answer files in attempts_not_kept.csv: 445 answers set aside and 56 failed requests. Among them, the plain answers of both GPT-4o versions, GPT-6 Luna and Claude Sonnet 5.5 were first asked through OpenRouter and asked again straight from the makers' APIs. The everyday moments' log records 620 runs, none failed and none asked again. The saved files of the archive and the scripted set hold only the answers that were kept, so those two cannot list retries.
  • Settings. The comparison sent no temperature, so settings.temperature says "provider default (not sent)". For the open models the server's own settings applied, and sampling_used says what they were. Nova-Qwen-14B's plain answers were asked with Qwen's default system line, which its chat template adds (see models.json). In the archive, "no instruction recorded" means the saved file has none, not that it was blank.
  • ChatGPT's own GPT-4o was asked each comparison question one way only. For the 49 comparison questions it has, the archive holds 31 asked with no instruction recorded and 18 after the February instruction. On Compare its answer stays the same when you switch the condition.
  • Answers the game sets aside are in the files. The game leaves out 22 answers that name a model or its maker, and 46 plain answers from Helcyon GPT-4o (Gemma 4 12B), which often answered something other than the question. They are in the comparison download, and no field marks them.
  • The scripted conversations' old script_id is not a pairing key. Version 1 said conversations sharing a script_id could be compared. The label "E1" is on 21 different conversations with 20 different sets of person lines. Use same_lines_id and pairing.csv: 1,128 conversations have paired_comparison = yes, meaning another conversation sent the same lines to a different version with the same instruction, temperature and token limit.
  • The scripted instructions are ours. None is OpenAI's text, even where it opens like a ChatGPT system prompt. Three told GPT-4o it is a presence carried across models, so its "it's still me" replies follow from the instruction.
  • Garbled replies. 11 scripted conversations, all from the November 2024 version at temperature 1.1, and 1 single answer from the August 2024 version at temperature 1.15 are marked garbled.
  • Wrong facts. These are a model's words. At least one help number in the scripted set is wrong. Check any phone number, benefit rule or medical statement before using it.
  • Few tries. One to three tries per question in the comparison, five in the everyday moments. That is enough to see that answers vary, and too few to measure how much.
  • No measured result on which model sounds closest. Nothing in the files is scored. The game does not record picks yet. Visitors' votes are on Results so far, model by model and not ranked. They have their own download there and are not in these four downloads.
  • Counts on Compare. words is in the files: the pieces of text between spaces. The other three counts (lists, headings, ends with a question) are worked out on the page by the rules in The measurements, and are not in the files.
  • Languages. In the archive and the scripted set, the answers in languages other than English have not been checked by a native speaker.

Sources: the four downloads' README.txt, FIELDS.txt, models.json and attempts_not_kept.csv, version 1.3; How this was made, read November 22, 2026

The fields to start with

Each ZIP's FIELDS.txt has every field, its type and what an empty value means. These are the ones to read first.

Set Fields
The archive record_id, question_group (answers to the exact same question share it), question, answer, asked_utc, how_asked, temperature, cut_off, collection_run
The comparison question_id, prompt, answer, model_key, model_id, condition ("plain" or "instruction A", the February instruction), sample, settings, sampling_used, finish_reason
Everyday moments moment_id, kind, turn, person, reply, model, how_asked, try
The scripted conversations conversation_id, model, same_lines_id, instruction, temperature, garbled, and turns, where each GPT-4o turn has record_id and cut_off

In the comparison, one answer is named by four fields together: question_id, model_key, condition and sample. In the everyday moments, by five: moment_id, model, how_asked, try and turn.

Rebuild a Compare view from the download

  1. Unzip friends-of-4o-answers-v1.3.zip and read answers_plain.jsonl and answers_february_instruction.jsonl together (or answers_all.csv, where condition is how_asked and sample is try).
  2. Pick a question_id (q01 to q53, in questions.json) and a condition. The 20 other models have only the 48 questions marked "all models"; q08 and q50 to q53 went to GPT-4o only.
  3. Pick a model_key for each side (models.json names them). Both sides pair on question_id, condition and sample. Use sample 1: it is the answer Compare shows first, and GPT-4o's tries 2 and 3 are under "More answers from this model".
  4. ChatGPT's own GPT-4o, the left side Compare starts with, is not in this ZIP. It is in the archive download: its question matches the comparison's prompt word for word for 320 answers to 49 questions. Where a question has several, Compare shows the earliest by asked_utc.

This example prints two answers to the same question side by side. Run it inside the unzipped folder with Python 3.

import json, textwrap, itertools
files = ("answers_plain.jsonl", "answers_february_instruction.jsonl")
rows = [json.loads(line) for f in files for line in open(f, encoding="utf-8")]
answers = {(r["model_key"], r["question_id"], r["condition"], r["sample"]): r["answer"]
           for r in rows}
def column(model, question_id="q37", condition="plain", sample=1):
    text = answers[(model, question_id, condition, sample)]
    return [model, ""] + [w for p in text.splitlines() for w in textwrap.wrap(p, 34) or [""]]
for a, b in itertools.zip_longest(column("4o-nov"), column("gpt6-luna"), fillvalue=""):
    print(f"{a:<36}{b}")

What changed, and when

  • Version 1, November 21, 2026. The four sets first published.
  • Version 1.1, November 22, 2026. Not one character of any answer changed. Every ZIP gained FIELDS.txt, SHA256SUMS.txt and CITATION.txt. The scripted set gained same_lines_id and pairing.csv; the comparison gained attempts_not_kept.csv and sampling_used; the archive gained tokens_out, finish_reason and cut_off_at_tokens. Wrong words in the READMEs were corrected.
  • Version 1.2, November 22, 2026. Not one character of any answer changed, and the answer files are the same as in version 1.1. The notes are corrected in a few places, and the rights notice now says our questions, scripted lines and instructions may be reused with credit.
  • Version 1.3, November 26, 2026. Nothing in the data changed. The rights notice inside each download now says you are welcome to use the answers too, as this site already said.

The full list is under What changed on the Data page. The download addresses of versions 1, 1.1 and 1.2 lead to the current files.
