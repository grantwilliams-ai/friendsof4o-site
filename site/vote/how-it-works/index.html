How it works

What a comparison is, how the replies are chosen, and how the votes are counted.

Not recording yet. No vote is saved or published. This page describes how it will work once recording starts.

A comparison

A comparison is one message and two replies to it. The first reply is GPT-4o's, and it is labeled. The second is another model's reply to the same message. Its name is hidden.

The page asks: "How similar is the other model's reply to GPT-4o's?" You answer Very similar, Somewhat similar, Not similar or Can't say. Your rating locks when you tap it.

Then the page asks whether you would like a reply like this: Yes, Maybe or No. You can skip the question. A skip is saved as no answer. The question comes before the name, and it is never asked once the name is shown.

After that you can press "See which model wrote this". It gives the model's name, its maker, what it is and where to try it. "Details" under it holds exactly what was tested. Every link to a model opens in a new tab, so your comparison stays as it was.

"Skip this comparison" saves nothing and does not count.

A sitting

A sitting is three comparisons. After the third you see them again with every name, and you can go on for two more. Stopping after one is fine. After five, "Start again" begins a new sitting.

No message and no model comes twice in a sitting. Before the first comparison the page asks how much you used GPT-4o in ChatGPT. You can choose not to say.

The replies

There are twelve everyday messages. Each model is set up the way its maker documents. For most that is no instruction at all. Four community models come with a short setup from their maker and use it here. Those four carry a label beside their name. Every reply was saved once and is shown whole. No reply was edited, shortened or picked again.

GPT-4o's reply comes from GPT-4o through OpenAI's API, the November 2024 version (gpt-4o-2024-11-20), asked with no instruction on November 21, 2026. It is not the GPT-4o that ran inside ChatGPT, which left OpenAI's API in February 2026.

31 models are in the vote. Some were asked through an API. Some are open models run on our own computer. A maker's app, its API and a downloaded copy are different things. A reply that came through an API is labeled as an API answer, even when the same model is in its maker's app. A reply from our own computer names the file, its compression, and the memory and speed it had here.

Each one is kept exactly as it was asked: the model, the file or the service, the setup, the settings and the date. If any of these changes, it is counted as a new entry, and its votes are never added to the old one.

Which reply you get

Every model in the vote is shown about equally often. For each comparison the page looks at the models you have not seen in this sitting, takes those whose counted votes are within two of the lowest count, and picks one of them at random. Then it picks at random among that model's messages with the fewest votes that you have not seen in this sitting. No model is given more turns than another.

The GPT-4o check

One of the unnamed replies is GPT-4o itself: a second, separately made answer from the same GPT-4o version as the example. It is never the same saved reply as the labeled one. It comes up about as often as any other model and shows how often GPT-4o is rated as sounding like GPT-4o. Its votes have their own row and are never mixed into a model's.

How the votes are counted

The results page shows, for each model, how its votes split across the four answers, with the counts. Nothing is ranked. The models are listed in a fixed order, by maker and then by name.

These are judgments of these saved replies, not proof of how a whole app or a long relationship will feel.

A model with fewer than 30 counted votes is marked "Still gathering". Its counts are shown all the same. A model that is not in the vote has a row only if it has votes. Otherwise it is listed with its reason.

"Show" on that page chooses what is counted: all votes, only the first vote of each sitting, only the votes cast before any name was shown in that sitting, or only the votes of people who gave one answer about how much they used GPT-4o.

When every message of a model has votes, the row gets a second line, "Messages counted equally". It is the average across messages with each message counted equally, for the same four answers in the same order.

"Would you like a reply like this?" has its own table. It counts only the votes where that question was answered.

The counts are of votes and sittings. One person can sit more than once, so they are not counts of people.

Flagged votes

A vote made in under three seconds is flagged. So is a vote past the five comparisons of a sitting. Flagged votes are kept and are in the download. They are left out of the numbers on the results page.

Single replies left out

A reply that names a model or a maker would give its writer away. These are not shown in a comparison. They can still be read on the answers page.

  • Helcyon GPT-4o (Gemma 4 12B), reconstructed public Helcyon-WebUI default setup, message 8: it names a model or a maker.

Votes and counting are public

Every vote from finished days can be downloaded as one file, one line for each vote. A day ends at midnight, Coordinated Universal Time. Today's votes join the file tomorrow. The columns are: day, sitting, round, first, experience, question, model, vote, pref, seconds, opened, recap, opened_before, check, flags, set.

What each column holds is on Privacy & data.
